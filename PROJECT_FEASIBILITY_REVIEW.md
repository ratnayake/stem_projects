# Review of the 20 club projects

Reviewed: 14 October 2026.

> **Historical audit:** This review describes the original guides and procurement plan. They were subsequently revised; use the [revised procurement plan](School_Electronics_Club_Procurement_Plan_LKR_50000.md), current project guides and [validation record](VALIDATION.md) for the latest instructions.

All 20 ideas are valid educational projects, but the current procurement list and guides do **not** establish that all 20 can be built successfully as written. Most can be completed after small corrections. Project 15 needs a different sensing component or a substantial redesign; projects 07 and 19 require resolving the LDR specification; the motor and servo projects need a proper power plan.

This is a document, code, and component-specification review, not a physical build certification. I read all 20 guides and both procurement documents, checked the BOM arithmetic, checked the five Python blocks for syntax, and consulted supplier listings and manufacturer documentation. Arduino CLI is unavailable here; no sketches were compiled for their target boards, and MakeCode API compatibility and hardware operation remain to be tested. The two procurement documents currently contain identical text.

## Project-by-project verdicts

“Doable” means the core inventory supports the demonstration, assuming access to computers, suitable USB data cables, and ordinary craft materials. “Conditional” means the guide needs corrections or a component/power specification must be resolved first. Parts are reused between sessions.

| # | Project | Verdict | What must change or be checked |
| :-- | :-- | :-- | :-- |
| 01 | Micro:bit radio messenger | **Doable** | Two V2 boards provide the necessary hardware. Add four AAA cells for portable use, or use USB power. A micro-USB data cable is needed; an Arduino starter kit cable is not necessarily compatible. Align the button descriptions: code uses B to send an emoji, not cycle backwards or send “OK.” Indoor range is an experiment, not a guarantee. |
| 02 | Compass and step counter | **Conditional: counting logic** | Compass is feasible after calibration. `Gesture.SHAKE` counts shake events, not reliably one event per walking step. Replace it with tuned acceleration peak detection, a minimum step interval and rearm threshold; compare against manually counted steps. Describe the current version as a compass and shake counter. The display loop can overwrite the logo-triggered count. |
| 03 | Classroom noise monitor | **Doable, with limitations** | V2 includes the microphone and speaker. The reading is relative 0–255, not calibrated decibels. The code always draws a bar graph; it does not implement the overview's quiet happy face. The graph can overwrite warning icons. Add a display state and alarm cooldown; test whether its own warning sound triggers further events. |
| 04 | Tilt maze | **Doable** | All required electronics are onboard. The implementation moves one grid step per loop rather than simulating momentum, and the goal is steady rather than blinking. These are documentation discrepancies, not build blockers. Test all movement directions on the physical board. |
| 05 | Micro:bit servo gauge | **Conditional: servo power** | Supply the SG90 from a suitable external regulated supply, connect its ground to micro:bit ground, and use P0 only for the signal. Do not connect external 5V to the micro:bit 3V rail. A power module and battery clip are not themselves a power source. Verify breakout routing and servo signal compatibility. The onboard temperature reading is an approximate board/processor temperature, not an accurate room thermometer. |
| 06 | Traffic signal | **Conditional: scope and buzzer** | Three LEDs and one button support a **single traffic signal with a pedestrian request**, not a four-way intersection. The code stays green until a request; it does not cycle automatically. Resolve LED colours, through-hole resistors, buzzer current and drive method. Requests during long blocking delays can be missed. Rename the project or add a second independently controlled road signal and corresponding logic. |
| 07 | Automatic street lamp | **Conditional: LDR mismatch** | The linked module is specified as digital switching output, whereas the guide requires AO and `analogRead()`. Use its DO output with revised code, or procure an AO module/bare LDR divider. Measure bright/dark polarity before choosing thresholds. Complete LED cathode-to-ground wiring. Keep the relay load to the demonstrated low-voltage LED circuit. The relay cannot perform the proposed 20%/100% dimming; that extension needs an appropriate transistor/PWM circuit. |
| 08 | Reaction tester | **Conditional: code will not compile as printed** | `Serial.println("` is followed by a literal newline before `Starting grid sequence...");`. Replace it with `Serial.println("\nStarting grid sequence...");`. Check false starts throughout the light sequence, wait for released buttons, debounce inputs, and report unpressed players as timeout rather than 0 ms. Resolve the active/passive buzzer mismatch. The existing timer uses `millis()`, not microsecond timing. |
| 09 | Morse trainer | **Conditional: buzzer and input filtering** | The button, LED and decoding concept are feasible. Use a passive piezo for the specified 750 Hz sidetone, or use on/off control of the active buzzer for a fixed-pitch trainer. Verify GPIO current or add a driver. Filtering only presses shorter than 40 ms does not fully debounce the switch; a brief release bounce can split a long press. Bound the input buffer for prolonged use. |
| 10 | Ultrasonic alarm | **Conditional: calibration and buzzer** | The HC-SR04 and board are suitable for a classroom demonstration facing a stable reflecting surface. Reject timeout readings during baseline calibration instead of averaging the 999 cm sentinel. Provide an explicit reset/disarm method; the current alarm latches until reset. The code detects closer objects, not every change or loss of echo. Resolve buzzer drive and pitch. Treat this as a demonstration, not a dependable security installation. |
| 11 | Indoor weather display | **Doable after assembly** | The DHT11, LCD and backpack are listed. Solder the backpack's 16 connections to the LCD if supplied separately, verify its I2C address with a scanner, and specify compatible LCD/DHT libraries and dependencies. Confirm the DHT module has its data pull-up. Suitable for classroom temperature/humidity trends; showing a decimal does not improve sensor accuracy. |
| 12 | Ultrasonic measuring tape | **Conditional: invalid readings** | Electronics are available, with the same LCD assembly requirements as project 11. A timeout is currently substituted with 400 cm and averaged, producing misleading measurements. Reject invalid samples and show “Out of range.” Increase the 20 ms inter-ping gap according to the purchased sensor's specification. The code averages rather than taking a median and displays cm/inches, not mm. Complete LCD power and button-to-5V wiring. Add a battery only if portable operation is required. |
| 13 | Smart dustbin | **Conditional: power and mechanics** | Feasible for a small lightweight cardboard lid. Add a correctly sized external servo supply and common ground, and explicitly wire sonar VCC/GND. Recheck for an obstructing hand before closing; the present four-second delay closes regardless of presence. Confirm the small breadboard can accommodate the Nano and wiring, or use a listed full-size board. A Nano cannot be safely powered merely by connecting a 9V clip to its 5V rail. |
| 14 | Parking barrier | **Conditional: power and clearance** | Feasible as a light scale model with external servo power and complete supply/ground wiring. The sonar sees the approach zone; it does not prove the space under the barrier is clear. A timeout returns 999 and permits closure. Use explicit invalid-reading handling and, if demonstrating clearance interlocking, a second sensor covering the barrier zone. |
| 15 | Secret knock lock | **Needs a different sensor or redesign** | The linked DC-powered active alarm is not a bare piezo knock sensor. Add a passive piezo disc and the appropriate input circuit, including a 1 MΩ bleed resistor and voltage protection as required. Two 10 kΩ resistors are 20 kΩ, not an equivalent substitute for 1 MΩ; the BOM and wiring also disagree about resistance. Add external servo power and use only a light model latch. Alternatively redesign this around the micro:bit V2 microphone, retaining rhythm recognition but replacing the Arduino sensor code and wiring. |
| 16 | Dual motor controller | **Conditional: motor supply and jumpers** | The motors and L298N support the concept. Use an adequately rated AA battery pack or other motor supply; do not rely on a rectangular PP3 9V battery or a small breadboard regulator. Remove ENA/ENB jumpers before attaching PWM wires. Specify the separate regulator-enable jumper and 5V logic-power arrangement for the exact module; do not join two regulator outputs. Keep a common ground. Account for L298N voltage loss and the motors' ratings. |
| 17 | Obstacle-avoiding rover | **Conditional: power integration and sensor failure** | Feasible after project 16 works. D5/D6 motor PWM avoids the Uno Servo library's Timer1 PWM conflict on D9/D10; D9/D10 remain usable as digital direction pins here. The proposed four-AA supply to Uno Vin is below the recommended 7–12V range and can sag under load. Provide suitable board power and a regulated servo rail. Remove enable jumpers. A missing echo currently becomes 300 cm and commands forward motion; stop/retry on invalid readings. Turn duration and stopping distance require physical calibration. |
| 18 | Bluetooth RC car | **Conditional: power, UART and fail-safe** | Feasible with a compatible Android Bluetooth Classic/SPP device and an app configured to send the exact F/B/L/R/S characters. Use project 16's corrected power plan. Explicitly draw the HC-06 RX divider: 1 kΩ from Arduino TX to RX node, 2 kΩ from node to ground; two 1 kΩ resistors in series can provide 2 kΩ. Hardware D0/D1 is shared with USB serial: disconnect HC-06 TX from D0 for uploads and avoid simultaneous competing transmitters. Add a command timeout and explicit startup stop. The current car continues its last motion indefinitely when the link is lost. |
| 19 | Solar tracker | **Conditional: analog sensors and servo power** | The algorithm requires two analog light readings; the linked digital-only modules cannot provide the claimed differential measurement. Use two confirmed AO modules or two bare LDR voltage dividers. Add external servo power, calibrate sensor balance, and check that movement reduces the error rather than driving to an end stop. Feasible as a light-following cardboard model. No solar panel is listed, so it does not demonstrate electricity generation or verify the claimed energy gain. |
| 20 | Soldered continuity tester | **Conditional: resistor and consumables** | The active DC buzzer is appropriate for this on/off circuit. At 9V with an approximately 2V green LED, 220Ω passes about 32 mA and dissipates 0.22W, too close to a 0.25W resistor's rating and above many indicator LEDs' normal current. Use the listed 1 kΩ through-hole resistor instead: about 7 mA and 0.049W. Add an actual 9V battery, probe wires/clips, insulation and enclosure. This circuit indicates a conducting path; it does not establish resistance below 1Ω. Use only on disconnected, unpowered loose cables. A meter reading includes test-lead resistance and need not be exactly zero. |

## Shared blockers in the purchasing plan

1. **Power and cables are incomplete.** Battery holders and snap clips do not include batteries. Confirm USB data cable types: micro-USB for micro:bit, the actual Uno connector, and Type-C for the listed Nano. Computers and an Android phone are external resources. Servo projects need an actual regulated source rated for peak/stall current, not just a regulator module. For a single small SG90 model, a regulated 5V supply with roughly 1A available is a practical starting point, subject to the purchased servo's specification. Do not distribute high motor currents through thin signal jumpers or breadboard rails.
2. **LDR specification contradicts the guides.** The supplier describes the linked part as DO digital output. Confirm the delivered board has AO before using any analog guide. Changing project 07 to digital input is easy; retaining project 19's analog comparison requires suitable sensing hardware. [Supplier LDR specification](https://www.duino.lk/product/photoresistor-ldr-light-sensitive-sensor-module/).
3. **Buzzer types are mixed up.** The linked buzzer is a DC continuous-sound alarm, which indicates an active device. It can provide switched beeps but is not established as suitable for programmable tones or reverse-use knock sensing. Its listing does not establish safe direct GPIO current. Confirm current and use a transistor driver if required, or choose a suitable low-current passive piezo for the tone projects. Project 20 can retain the active buzzer. [Supplier buzzer listing](https://www.duino.lk/product/dc-3-24v-electronic-buzzer/).
4. **The resistor link is wrong for the stated assortment.** It points to a 2 kΩ 1206 SMD pack, not 220Ω/1kΩ/10kΩ through-hole breadboard parts. Order the values and packages explicitly, including the 1 MΩ resistor if retaining project 15. For button projects, `INPUT_PULLUP` with the button to ground can remove external pull-downs, but requires inverting the input logic. [Linked resistor listing](https://www.duino.lk/product/2k-ohm-1-4w-smd-resistor-1206/).
5. **Other ordering links need reconciliation.** The LED label promises assorted 5mm colours while its URL identifies a red 3mm product. Confirm separate red, yellow and green quantities. The battery-holder link points to a micro:bit bundle, not an unambiguous LKR 160 holder. Glue stick text says 7mm × 300mm while the URL says 10mm × 180mm; confirm the glue gun's actual diameter. Do not order by these descriptions without matching the SKU.
6. **The robot kit is not the stated chassis-only product.** The retrieved listing is an all-in-one kit at LKR 5,990–7,890, not LKR 1,990. It lists an Uno with cable, L298N, sonar, servo and AA battery box as well as the chassis. Confirm the selected variant and either select a chassis-only product or remove duplicate components from the separate BOM. The base kit's AA box does not include cells. [Supplier robot kit listing](https://www.duino.lk/product/duino-obstacle-avoidance-smart-robot-car-kit/). These retrieved prices are not a quotation or a complete current-price audit.
7. **Permanent-build consumables are missing.** Specify probe clips, hookup wire, insulating sleeves/tape or heat-shrink, and suitable mounting materials. Confirm what is actually inside the O/L starter kit before counting any unlisted parts. Allow adult-supervised soldering, ventilation and eye protection for the school workshop. Optocouplers alone do not establish isolation when module grounds are joined; use low-voltage loads for the demonstrations.

## Scheduling and reuse

The stated standalone inventory has two micro:bits, two Unos including the starter-kit Uno, two Nanos, one pair of drive motors/chassis, three sonar modules, four servos, two LCD/backpack pairs, two LDR modules and two buzzers. Do not count possible extras in the robot kit until the order is clarified.

These are **20 sequential activities**, not 20 finished devices that can remain assembled at once. Projects 16–18 share the same motor pair; 17 and 18 share one car. Project 19 uses both LDRs, preventing project 07 from using one simultaneously. Project 01 uses both micro:bits. Permanent assembly of project 20 consumes an LED, resistor, buzzer and clip that other lessons may need.

A practical three-team session is project 01 (both micro:bits), project 11 (one Uno, one LCD/DHT), and project 16 (the other Uno and motor pair). This fits the controller and sensor quantities once the power issues are resolved. Treat the workshop tools as shared supervised resources.

Start with 01, 03, 04 and 11; introduce LEDs/buttons and corrected 06–10 next; build corrected 12–14 and 19 after establishing reliable servo power; teach 16 before progressing to 17/18. Keep 15 until its sensor circuit is corrected. Assemble 20 after resistor selection and workshop consumables are settled.

## Evidence and physical acceptance checks

- Official MakeCode documentation defines the microphone output as a relative value from 0 to 255. Verify threshold behaviour and alarm cooldown in a quiet room and under controlled claps. [MakeCode sound level](https://makecode.microbit.org/reference/input/sound-level).
- Official micro:bit guidance recommends separate servo power with a common ground. Confirm correct voltages with a multimeter before connecting the board; sweep an unloaded servo and then the lightweight model while checking for resets. Never inject 5V into a micro:bit rail. [micro:bit servo wiring](https://support.microbit.org/support/solutions/articles/19000101864-using-a-servo-with-the-micro-bit).
- Arduino's knock example uses a piezo element and a 1 MΩ parallel resistor. Follow a suitable protected sensor circuit and calibrate against taps before attaching the model lock. [Arduino knock example](https://docs.arduino.cc/built-in-examples/sensors/Knock?setlang=it).
- Arduino specifies 7–12V as the usual recommended Uno Vin supply and requires accounting for peripheral current. Test board and servo rails during motor startup. [Arduino power guidance](https://support.arduino.cc/hc/en-us/articles/360018922259-What-power-supply-can-I-use-with-my-Arduino-board).
- The L298 datasheet specifies substantial bridge voltage drop (typically 1.8V at 1A), so supply voltage and actual motor terminal voltage must be checked together. Test project 16 with wheels raised before floor testing. [ST L298 datasheet](https://www.st.com/resource/zh/datasheet/l298.pdf).
- Upload each sketch with the selected board and explicit library versions. Verify sonar readings against a ruler and check disconnected/no-echo handling. Test project 08 for false starts, held buttons and a player who never presses; test project 18 by disconnecting Bluetooth while driving slowly and confirm the timeout stops the wheels.

None of these physical checks has been performed in this review. The current guides should be corrected and then tested before being presented as complete, ready-to-build instructions for students.
